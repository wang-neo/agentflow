# Rubric: 文档自审（S3 doc_self_review）

对 `tech_doc` 产物按以下维度逐项判定 pass/fail，输出证据。Judge 独立判定，不与生产者共享上下文。

## 判定维度

1. **最小性**（权重 0.25）：每个改动点都直接服务需求条目；无镀金、无超前设计、无「顺手重构」。
   - 证据要求：改动点 ↔ 需求条目映射表存在且完整。
2. **完整性**（权重 0.25）：需求条目 100% 覆盖；明确「范围外」清单。
3. **可验证性**（权重 0.2）：每条验收标准可自动化测试或可人工复验（有明确步骤/期望）。
4. **风险与回滚**（权重 0.15）：兼容性变化逐条列出+影响面+缓解；回滚方案具体可执行。
5. **测试计划**（权重 0.15）：覆盖每个验收标准+边界；先红后绿的回归策略。

## 输出格式（固定 JSON）

```json
{
  "decision": "pass | fail | needs_fix",
  "confidence": 0.0,
  "reasons": ["维度级结论，逐条"],
  "evidence": ["tech_doc.md:行号 或 需求条目ID"],
  "required_actions": ["fail 时必须给出的修复指令"]
}
```

## 判定规则

- 任一维度 fail 且该维度为必需（1/2/3）→ decision=fail
- 可选维度（4/5）单项 fail → needs_fix（要求补充，不整体否决）
- confidence >= 0.85 且 decision=pass → accepted
- 低于阈值 → 按配置处理（默认不升级人工，回退修复）
